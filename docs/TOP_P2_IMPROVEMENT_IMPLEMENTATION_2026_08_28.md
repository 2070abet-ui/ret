## 6. 発見された問題（追加実装はせず報告のみ）

QAの過程で、設計時には想定していなかった副作用を1件発見した。指示に従い、その場での修正は行わず、以下のとおり報告する。

### P2：「↓」ミニチップの背景色が親セクションの背景色と同化し、意図した「独立した操作対象に見える」効果が限定的

- **問題**：1b案で採用した`.purpose-anchor`の背景色`--color-primary-subtle`（`#FDEEE8`）が、チップの親要素である`.purpose-section-top`自体の背景色（同じく`--color-primary-subtle`）と**完全に同一トークン**だったため、実装後の画面ではチップの背景が周囲に溶け込み、「丸い縁取りのある独立したボタン」としては視認しにくい。
- **実画面上の根拠**：PC本番相当のローカルビルドで`.purpose-section-top`をズームスクリーンショットで確認したところ、「↓」の文字色（オレンジ）は視認できるが、その周囲に意図した円形の背景・境界はほぼ見えない。
- **補足（改善した点）**：文字色を`--color-text-faint`（薄いグレー）から`--color-primary`（オレンジ）に変更したことで、**文字そのもののコントラストは明確に改善**しており、「グレーで気づかれない」という当初の問題（P2-1）は部分的に解消されている。「チップ化による形状差」という2段目の狙いが未達成という状態。
- **影響範囲**：目的で探すセクション（TOP専用）の視覚効果のみ。機能（クリック・アンカー遷移・`aria-label`）は正常に動作しており、実害はない。
- **改善案（実装は行わない）**：チップの背景色を、親セクションとは異なるトークンにする。候補は次の2つ。
  - (a) `background:var(--color-surface)`（白）にし、チップを「小さな白いボタン」として親のピンク系背景から浮き上がらせる。
  - (b) 背景chipをやめ、文字色変更のみ＋下線を残す、という1a相当の案に縮小する（実装済みの文字色変更はそのまま活かし、背景・角丸のみ削除）。
- **重要度の判断**：機能に支障はなく、文字色変更単体でも当初のP2指摘（発見性の低さ）を一定程度改善しているため、公開停止や緊急修正を要する水準ではない。ただし「1b案の意図を完全には実現できていない」という事実として、次回の改善サイクルで扱うことを推奨する。
