# UIビジュアルデザイン監査・デザインシステム方針（2026-08-28）

作成日: 2026-08-28
位置づけ: [[UI_DESIGN_PRINCIPLES]]（意思決定支援の機能原則＝Layer1）を土台に、本ドキュメントは**見た目そのものの洗練度（色・余白・タイポグラフィ・カード・情報密度＝Layer2「ビジュアルクラフト」**を監査し、標準を明文化する。
**本監査は完全READ ONLY。コード・data/config・実装の変更は一切行っていない。** `python tools/build.py`で`site/`を再生成し、Playwrightで自サイトの実画面（PC/モバイル）を確認したうえで、外部の優良サイトを実機調査し、比較・分析した。

参照した既存監査: [[UI_DESIGN_PRINCIPLES]]（機能原則、本監査はこれを破らない）、[[PRODUCT_IMAGE_LICENSING_AUDIT_2026_08_27]]（15/16社中0社が画像利用可、写真導入は不可という制約）、[[COMPETITOR_UX_FUNNEL_AUDIT_2026_08_28]]（競合の意思決定導線比較、本監査は「見た目」に特化した別軸）、[[DIAGNOSIS_COMPARE_CTA_FUNNEL_AUDIT_2026_08_28]]（診断→比較→CTA導線は凍結済み、本監査はそれを変更しない）。

## 0. 結論（先出し）

自サイトの現状デザインは「情報の誠実さ・検証状態の一体化」という機能面では競合に無い強みを持つが、**ビジュアルクラフトの層では「均質すぎて単調」という弱点がある**。原因は機能不足ではなく、①写真が使えないという制約下で視覚的な起伏を作る手段が乏しいこと、②タイポグラフィ・カード・バッジのバリエーションが必要最小限に留まっていること、の2点。

優れたサイト（kakaku.com・mybest.com・Linear・Oisix）から抽出した解決策はいずれも「新機能」ではなく「既存トークンの運用強化」で実現できる。具体的には、(1) 写真の代わりに**大きな数字（タイポグラフィ）を視覚アンカーにする**、(2) 比較表の**数字を縦に揃え、行間を広げる**、(3) 詳細ページの**主役ブロックだけをアクセント罫線で区別し、脇役は罫線を減らして余白だけで区切る**、の3点が最も費用対効果が高い。新しい色相・写真・スコア表示は導入しない。

## 2. 現状のビジュアルデザインシステム（`tools/sitegen/templates.py` `_CSS`）

- **色**: プライマリ`#E8552D`（オレンジ、再ブランディング禁止と明記済み）＋ニュートラル（クリーム系背景`#FAF7F5`・白サーフェス）＋検証状態4色（confirmed緑/derived青/pending橙/uncollected灰）のみ。装飾目的の色は無い。
- **タイポグラフィ**: Hiragino Kaku Gothic ProN/Noto Sans JP。`--text-display`〜`--text-micro`の7段階スケール＋価格専用`--price-figure`。
- **余白**: 4px基準（`--space-1`〜`--space-8`）。
- **角丸・影**: `--radius-sm/md/lg`、`--shadow-sm/md`のみ（ネオモーフィズム・強いドロップシャドウ等は無い）。
- **カード**: `.card`/`.svc-card`は白背景＋細罫線＋shadow-sm＋radius-mdで統一。Hero/trust-panelのみshadow-mdで一段階格上げ（コード内コメントに「Tier2」の記載あり、意図的な階層設計）。
- **バッジ**: 検証状態バッジ（記号+ラベル+色）、タグ（オレンジ薄ピル）、初回/お試し強調バッジ（塗りつぶし、[[PRICE_FAIRNESS_UI_FIX_FINAL_AUDIT_2026_08_28]]で追加済み）の3種のみ。★・メダル・クラウン等の装飾記号は無い。
- **画像**: 一切使用しない（[[PRODUCT_IMAGE_LICENSING_AUDIT_2026_08_27]]の結論により方針として確定済み）。
- **比較表**: `<table>`は縦罫線を持たず横罫線（`border-bottom`）のみ、モバイルは横スクロール＋カード切り替え。

**総評**: 色数・装飾要素を絞り込んだ「誠実で静かなデザイン」であり、これ自体は競合（特にkakaku.comの広告・装飾過多）に対する強みである。弱点は、絞り込みすぎた結果、**視覚的な起伏（メリハリ）が最小限になっている**こと。

## 3. 優良サイト調査で抽出したパターン

### 3.1 ファーストビュー
- **kakaku.com**: 広告バナー2本＋パンくず＋トレンド解説＋執筆者プロフィールが折り返し前に並び、情報過多（反面教師）。
- **mybest.com**: 大きな合成写真＋手書き風の吹き出し（「100食以上購入して」）で最初の1画面に検証プロセスの物量を視覚的に伝える。写真が使えない前提では模倣不可。
- **linear.app**: 見出し以外は何も置かず、余白だけで「これから始まる」という余韻を作る。
- **自サイト**: テキストのみのHero＋CTA。情報は簡潔だが視覚的な「フック」が無い。

### 3.2 視覚階層
- **linear.app**: 罫線・カード・影を一切使わず、フォントサイズと余白の量だけで4プランを区別。太字の価格＋グレーの補足文という2段階のコントラストのみで十分に階層ができている。
- **mybest.com**: 王冠バッジ・色付きリボン・枠線色を変えることで「1位」を視覚的に飛び抜けさせる（自サイトはランキング化しない方針のため模倣不可、[[UI_DESIGN_PRINCIPLES]]8.1）。
- **自サイト**: 詳細ページの各カードが同じ白背景・同じ影のため、スクロールしてもセクションの主従が伝わりにくい。

### 3.3 余白
- **linear.app**: プラン間の余白が広く、罫線が無くても列の区切りが明確。外部記事（Setproduct）も「行間・列間の余白が十分であれば区切り線は最小限でよい」と指摘。
- **自サイト**: 比較表のセルpaddingは12px（`--space-3`）で、外部記事が推奨する「16px相当の行間でエラー率が下がる」という目安よりやや詰まっている。

### 3.4 色・背景
- **oisix.com**: 暖色のクリーム背景＋写真という組み合わせで「上質さ」を演出。自サイトも同系統のクリーム背景（`--color-bg:#FAF7F5`）を既に採用しており、方向性は一致している。
- **mybest.com**: オレンジ・赤・緑・黄が同一画面に混在し、セールチラシ的な印象。自サイトの「プライマリ1色＋ニュートラル」という制約の方が、金融比較サイト（NerdWallet等）に近い信頼感がある。**色を増やす方向の変更は推奨しない。**

### 3.5 タイポグラフィ
- **linear.app**: 価格の数字が圧倒的に大きく（本文の3〜4倍）、それだけで視線を集める。
- **自サイト**: `--price-figure`（1.375rem）は本文（1rem）の1.4倍程度に留まり、価格が「主役」であることの主張がやや弱い。trust-panelの`--trust-figure`（2rem）はより大胆に使われており、この使い方を他の主要指標にも広げる余地がある。

### 3.6 カード構造
- **mybest.com**: 番号付きリスト＋小さな正方形サムネイル（検証方法の説明）という「写真の代わりに使えるレイアウト」パターンが有効。サムネイルを汎用アイコンに置き換えれば自サイトでも模倣可能。
- **自サイト**: `.svc-card`は情報量に対して十分にコンパクトだが、全カードが同一の見た目のため「今どのサービスを見ているか」の記憶に残る手がかりが薄い（写真が無いため）。

### 3.7 商品画像
- 3サイトとも写真を前提にした設計（kakaku=製品写真、mybest=実食写真、oisix=料理写真）。**自サイトは権利上写真を使えないため、この軸だけは競合と同じ土俵に立てない**（[[PRODUCT_IMAGE_LICENSING_AUDIT_2026_08_27]]で確定済み）。
- 対策は「写真の代替視覚要素」を強化する方向のみ現実的（§5参照）。

### 3.8 CTA
- 3サイトともCTAの数・階層は[[UI_DESIGN_PRINCIPLES]]5章と概ね同思想（主役1つ・補助は控えめ）。**自サイトのCTAデザイン（btn-primary/secondary、44pxタップターゲット、hover時のtransform）は既に競合と同等以上の完成度**。追加の改善提案なし。

### 3.9 バッジ・強調表現
- **mybest.com**: チェックマーク付き箇条書き（✓ 取り扱いメニュー数が最多）で差別化ポイントを軽く見せる。自サイトの「向いている人」は地の文（段落）で書かれている箇所があり、スキャン性で劣る。
- **自サイト**: 検証状態バッジ（記号+色+ラベル）は既に「意味のある強調」として機能しており、外部記事が推奨する「一貫したアイコン+ラベルのペア」の模範例になっている。**この一貫性は競合にない資産であり、変更しない。**

### 3.10 情報密度
- 外部記事（LogRocket・Setproduct）の共通見解: 「グループ化・視覚階層・十分な余白・レスポンシブ対応」が比較表の核心。縦罫線を引かない・行間を確保する、という自サイトの既存方針は既にこの原則と一致している。
- 数字の桁揃え（tabular figures）・列内容に応じた文字寄せ（数字は右寄せ）は自サイトで未対応。

### 3.11 比較表
- 外部記事: 「列見出しは固定（sticky）して長い表でも意味を見失わせない」という推奨があるが、自サイトはsticky theadを実装していない。
- ソート・フィルタは自サイトに既に実装済み（[[PRICE_FAIRNESS_UI_FIX_FINAL_AUDIT_2026_08_28]]）。

### 3.12 モバイルUI
- 3サイトとも1カード1商品の縦積みは共通（自サイトも既に採用済み）。差は「ファーストビューに数字や写真の視覚アンカーがあるか」で、自サイトのみテキストのみ。

### 3.13 ページ間の統一感
- 自サイトはCSSカスタムプロパティによる一元管理で、ページ間の統一感は既に競合より高い（mybestは広告枠のデザインがコンテンツと不統一、kakakuはページごとに情報密度がまちまち）。**この一貫性は明確な強みであり、今後も新規コンポーネントは既存トークンのみで構成する。**

## 5. デザインシステムとして明文化（標準仕様案）

以下は**READ ONLYの提案**であり、実装は別途承認のうえ行う。

| 領域 | 標準とする方針 |
|---|---|
| **色** | 現行トークン（プライマリ`#E8552D`＋ニュートラル＋検証状態4色）を維持し、新しい色相は追加しない。色数を増やす方向の改善（mybest型の多色バッジ等）は導入しない。タグの属性区別が必要な場合も、既存の`--color-border-strong`によるoutlineトーンの範囲で表現する。 |
| **タイポグラフィ** | 現行の7段階スケールを維持しつつ、「主要な数字（価格・統計）は大きく見せる」という`--trust-figure`的な使い方を、TOPのHero・詳細ページの主要指標にも一貫して適用する。表内の数字には`font-variant-numeric: tabular-nums`の適用を検討する。 |
| **余白** | 4px基準のスケールを維持。比較表のセルpaddingは12px→16px相当への微増を検討する。セクションの区切りは「罫線」より先に「余白量の差」を使う。 |
| **カード** | `.card`/`.svc-card`の控えめな影＋細罫線を標準として維持する。「本当に主役の1ブロック」だけ左アクセント罫線（既存`.pros-highlight`パターン）で差別化し、それ以外は罫線・影を弱めて余白で区切る。ネオモーフィズム・強い影・グラデーションは導入しない。 |
| **商品画像** | 導入しない（既存方針を維持、[[PRODUCT_IMAGE_LICENSING_AUDIT_2026_08_27]]）。代替として「大きな数字（タイポグラフィ）」「汎用カテゴリの線アイコン（実写真ではない）」「既存の色帯ゾーン（`.purpose-section-top`パターン）」の3点で視覚的な起伏を作る。 |
| **CTA** | 現行のbtn-primary/secondaryの2階層・マイクロインタラクション（hover時のtransform）を標準として維持する。追加改善は不要。 |
| **バッジ・強調表現** | 検証状態バッジ（記号＋色＋ラベル）を標準の強調ボキャブラリーとする。星・王冠・メダル等の新しい強調記号は導入しない（[[UI_DESIGN_PRINCIPLES]]8章の恒久方針と一致）。 |
