## 1. 「目的で探す」の「↓」アンカーの発見性

### 現状の問題

`.purpose-services a.purpose-anchor`（アンカーの矢印リンク）が`font-size:11px`・`color:var(--color-text-faint)`（薄いグレー）と、隣接する本リンク（サービス名、`font:var(--text-body-sm)`＝14px・`color:var(--color-text)`）に比べて著しく弱いスタイルになっており、「別の操作対象」だと認識されにくい。

### 実画面上の根拠

`docs/TOP_UI_FINAL_AUDIT_2026_08_28.md`のPC本番URLズームスクリーンショットで、「シェフの無添つくりおき↓」のように矢印がリンク文字列に直付けされ、下線付きの本リンクと視覚的に一体化していることを確認済み。

### 最小変更案（3案比較）

| 案 | 内容 | 変更範囲 | 効果 |
|---|---|---|---|
| **1a. 色とサイズの微調整** | `color:var(--color-text-faint)`→`var(--color-primary)`（常時、hover待ちにしない）、`font-size:11px`→`13px` | `.purpose-anchor`の2プロパティ値変更のみ | 小。オレンジ色自体はチップ・タグ・価格など画面内で多用されているため、色を変えるだけでは「本リンクと同系統の何か」という程度の認識に留まる可能性がある |
| **1b. ミニチップ化（推奨）** | 背景色`var(--color-primary-subtle)`・角丸`999px`・独立した小さな円形/楕円ボタンにする | `.purpose-anchor`のCSS1ブロックの書き換えのみ（新規クラス追加なし） | 大。「文字装飾」ではなく「別の小さなボタン」という形状そのものが変わるため、色を変えるより発見性が上がる |
| **1c. 記号→短いラベルへ変更** | 「↓」を「一覧」などの短いテキストラベルに変更 | CSS変更に加え、`purpose_chips_block()`内の文字列（`aria-label`と表示文言）変更が必要 | 中。意味は伝わりやすくなるが、14箇所×2〜3文字増えることで`.purpose-services`の折り返し行数が増える可能性があり、間接的にレイアウトへ影響が及ぶ |

### 推奨：1b（ミニチップ化）

理由：CSS1ブロックの値変更のみで完結し、HTML・文言・データは一切変更しないため「最小変更」の要件に最も適合する。かつ「色」ではなく「形状（背景+角丸）」で異物感を出すため、1aより発見性の改善幅が大きい。1cはHTML文言変更を伴い、既存の折り返しレイアウトに波及するリスクがあるため見送る。

**設計値（実装時の参考）**：
```css
.purpose-services a.purpose-anchor {
  display:inline-flex; align-items:center; justify-content:center;
  font-size:11px; color:var(--color-primary); text-decoration:none;
  background:var(--color-primary-subtle); border-radius:999px;
  min-width:20px; height:20px; padding:0 5px; margin-left:2px;
}
.purpose-services a.purpose-anchor:hover { background:var(--color-primary); color:#fff; }
```

**付記（タップ領域について）**：`UI_DESIGN_PRINCIPLES.md` 6.3節はタップ領域44px以上を推奨するが、`.purpose-services`配下の既存の本リンク自体も密なインラインテキストリンク集合（`line-height:1.5`・14pxフォント）であり、現行デザインの時点で厳密な44pxを満たしていない。今回のミニチップも同じ設計言語の範囲内であり、**新たな後退ではなく既存パターンとの整合**という位置づけになる。将来的にタップ領域全体を見直す場合は、この指摘とは別の監査として扱うべきと考える。

### UX/購買導線への期待効果

「目的で探す」チップが単なる「情報の一覧」から「クリックして一覧内の該当カードへ飛べる操作」だと認識されやすくなり、目的入力→該当カード確認までの往復がスムーズになる。第2段階監査で指摘した「チップと一覧の断絶」の実効的な解消に直結する。

### 他ページへの影響

`.purpose-anchor`はTOPの`purpose_chips_block(..., with_anchor=True)`呼び出し時のみ出力される要素で、他ページ（`ranking.html`等、`with_anchor`未指定＝False）のHTMLには一切登場しない。CSSクラス自体は共有スタイルシートに存在するが、適用対象がTOP限定のため無影響。

### 回帰リスク

**極めて低い**。既存クラスの値変更のみで、新規クラス・新規DOM要素・新規JSは発生しない。色のコントラスト比（`--color-primary`のオレンジ地に`--color-primary-subtle`の薄い背景）は、既存の`.tag`（同系色の組み合わせ）で実績があるため視認性上の懸念もない。

## 2. Hero・目的・検証ゾーンの視覚的な境界

### 現状の問題

3ゾームの背景色トークンが極めて近い：

| ゾーン | 背景トークン | 実値 |
|---|---|---|
| ページ地色 | `--color-bg` | `#FAF7F5` |
| Hero | `--color-surface-alt` | `#FFF8F0` |
| 目的で探す | `--color-primary-subtle` | `#FDEEE8` |
| 検証カバレッジ（compact） | `--color-surface-alt` | `#FFF8F0`（**Heroと完全に同一値**） |

特に「Hero」と「検証カバレッジ」が**同一の背景色トークンを使っている**ことが、2ゾームの混同の直接原因になっている（検証カバレッジ側は左の太いオレンジ罫線1本だけで区別している状態）。

### 実画面上の根拠

`docs/TOP_UI_FINAL_AUDIT_2026_08_28.md`のPCフルページスクリーンショットで、Hero・目的で探す・検証カバレッジの3ブロックが縦に連続し、罫線・見出しを読まないと境界が判別しにくいことを確認済み。

### 最小変更案（3案比較）

| 案 | 内容 | 変更範囲 | 効果 |
|---|---|---|---|
| **2a. 検証カバレッジの背景をページ地色に戻す（推奨）** | `.trust-panel-compact`の`background:var(--color-surface-alt)`→`var(--color-bg)` | CSS1プロパティのみ | 大。Hero・目的の2ゾーンが「暖色の主役」として残り、検証カバレッジは「ページに溶け込みつつ左の罫線で識別できる控えめな帯」という、当初のE節設計（Tier2のうち検証は最も軽い扱いにする）が正しく実現される |
| 2b. 目的で探すの背景色を変更 | `.purpose-section-top`の背景をより彩度の高い値に変更 | 新規色トークンが必要になる可能性が高い | 中。「新しい色を勝手に追加しない」という既存原則（第1段階実装時の制約）に抵触するリスクがあるため非推奨 |
| 2c. 罫線・余白の強化のみ | 背景色は変えず、ゾーン間の`margin`を増やす、または`border`を追加する | CSS数プロパティ | 小。色の近さという指摘の根本原因には対処できず、対症療法に留まる |

### 推奨：2a（検証カバレッジの背景をページ地色に戻す）

理由：Hero・検証カバレッジが**同一トークン**を使っているという明確な原因に直接対処でき、変更は1プロパティのみで最小。新しい色トークンの追加も不要（既存の`--color-bg`を再利用するだけ）。Heroという「最重要ゾーン」の見た目には一切手を触れないため、第1段階で確立した「Heroが最も重い」という階層設計を保ったまま、検証カバレッジだけをより軽く後退させられる。

**設計値（実装時の参考）**：
```css
.trust-panel-compact {
  background:var(--color-bg); /* 変更: 旧 var(--color-surface-alt) */
  border:none; border-left:4px solid var(--color-primary);
  border-radius:var(--radius-sm); box-shadow:none; padding:var(--space-4) var(--space-5); margin:var(--space-4) 0;
}
```

### UX/購買導線への期待効果

「Hero（発見）→目的（絞り込み）→検証（信頼の裏付け、控えめ）→サービス一覧（評価）」という段階の違いが、テキストを読む前の一瞥で伝わるようになる。検証カバレッジが「もう1つの主役」ではなく「サービス一覧に入る前の一押し」という本来の位置づけ（前々回監査のA節で設計した役割）に、見た目としても一致する。

### 他ページへの影響

`.trust-panel-compact`は`trust_panel(coverage, num_services, compact=True)`のときのみ付与されるクラスで、TOP以外の呼び出し（`ranking.html`・`verification.html`、いずれも`compact`未指定＝False）には一切影響しない。通常の`.trust-panel`（他ページで使用）は本変更の対象外。

### 回帰リスク

**低い**。背景色トークンの差し替えのみで、テキスト色・バッジ色・罫線色はすべて既存のまま。`--color-bg`は既にページ全体の地色として使われており、その上に乗る`.trust-figure`（黒系）・`.vstatus`バッジ（各状態の専用色）・`.trust-note`（faintグレー）のコントラストは、現状の`--color-surface-alt`との組み合わせより悪化することはない（`#FAF7F5`は`#FFF8F0`よりわずかに暗いのみで、いずれも明るい背景であるため）。

## 3. サービス一覧を見た後の「診断ツール」再導線

### 現状の問題

診断ツール（`/tool/diagnosis.html`）へのリンクは、ヘッダーナビ（非sticky、スクロールで画面外に消える）とHero内CTA（ページ最上部から261px以内）の2箇所のみ。目的で探す・検証カバレッジ・サービス一覧（初期表示・展開後とも）・キャンペーン・こだわりのいずれのセクションにも診断への再導線がなく、特に「残りを見る」で15枚全件を見た後に「決めきれない」と感じたユーザーを診断へ戻す手段がない。

### 実画面上の根拠

本番URLで`a[href*="diagnosis"]`をDOMクエリした結果、`top:12px`（ヘッダー）・`top:261px`（Hero）の2件のみがヒット。モバイル総ページ高さ3195pxのうち残り約2900px（91%）に診断への導線が存在しないことを実測済み。

### 設計方針：2つの診断導線の役割を明確に分ける

| 導線 | 役割 | 位置 | 見た目 |
|---|---|---|---|
| **① Hero内CTA（既存・変更しない）** | 発見段階の主CTA。まだ何も見ていないユーザーに「絞り込む」という選択肢を最初に提示する | Hero内 | `.btn-primary`（最も強い視覚重み） |
| **② サービス一覧後の再導線（新設）** | 15枚（または初期表示分）を見た後、「多くて決めきれない」と感じたユーザーへの救済 | サービス一覧セクションの末尾 | `.text-link`（軽量、ボタン化しない） |

①と②は目的・タイミング・視覚的強さのいずれも異なるため、「1画面1主CTA」（`UI_DESIGN_PRINCIPLES.md` 5.3節）に抵触しない。②はあくまで「詳しく見る」「公式サイトを確認」といった各カードのCTAより弱い、文章の一部のような扱いに徹する。

### 最小変更案（3案比較）

| 案 | 内容 | 表示タイミング | 変更範囲 | リーチ |
|---|---|---|---|---|
| **3a. サービス一覧セクション末尾に常時表示（推奨）** | `{svc_more_block}`（「残りを見る」）の直後、`.service-list-section`の閉じタグ直前に、1行のテキストリンク「決めきれない場合は診断ツールで絞り込めます →」を追加。`<details>`の開閉状態に関わらず常時表示 | 初期表示（6/4枚）を見た時点で既に見える | `build_index_page()`に`<p>`要素1つ追加。新規CSSは不要（既存`.text-link`を流用） | 最大。「残りを見る」を使わずに離脱するユーザーにも届く |
| 3b. `<details>`内（展開後）にのみ表示 | 折りたたみ内の末尾（9枚のカードの後）に同様のリンクを追加 | 「残りを見る」をクリックして展開したユーザーのみ | 3aとほぼ同じ（`svc_more`の生成部に1行追加） | 限定的。「残りを見る」をクリックしないまま離脱する多数のユーザーには届かない |
| 3c. サービス一覧とキャンペーンの間に独立した帯を新設 | 「15社を比較する」「診断で絞り込む」の2CTAを横並びにした軽量セクションを新規に追加 | 常時表示 | 新規セクション（見出し・枠等）が必要 | 3aと同等だが、「大規模なレイアウト変更はしない」という制約に抵触するリスクがある |

### 推奨：3a（サービス一覧セクション末尾に常時表示のテキストリンク）

理由：
1. **リーチが最大**：`<details>`を開かないユーザー（3bでは届かない層）にも表示される。実際には初期6/4枚を見た時点で既にリンクが視界に入るため、「もっと見る前に診断に切り替える」という選択も可能になる。
2. **変更が最小**：新規CSSクラス不要（既存`.text-link`の流用）、新規セクション不要、`build_index_page()`内に1行のHTML追加のみ。
3. **CTA競合が起きない**：ボタン化せずテキストリンクに徹するため、「詳しく見る」（各カードのprimary CTA）・「残りを見る」（`.svc-more`のsummary）と視覚的に競合しない。Hero内CTAとは物理的に離れた位置（ページ下部）にあるため、同一画面内での二重CTA化も起きない。

**設計値（実装時の参考、文言は要相談）**：
```html
<div class="service-list-section">
  <h2>📊 主要サービス一覧</h2>
  <div class="service-grid">{svc_primary}{svc_extra}</div>
  {svc_more_block}
  <p class="price-meta" style="margin-top:12px;">
    決めきれない場合は <a class="text-link" href="/tool/diagnosis.html">診断ツールで絞り込む →</a>
  </p>
</div>
```
- `class="price-meta"`は既存の控えめな補助テキストスタイル（`font:var(--text-meta);color:var(--color-text-faint)`）を流用し、新規CSSを追加しない案。
- 文言は「30秒で」等の効果訴求は避け、事実ベースの短い案内に留める（`UI_DESIGN_PRINCIPLES.md` 5.3節「偽の緊急性を作らない」との整合）。

### UX/購買導線への期待効果

「発見（Hero）→絞り込み or 一覧閲覧（サービス一覧）→（決めきれなければ）診断へ引き返す」という周回導線が生まれ、15枚（または展開前の6/4枚）を見て離脱しかけたユーザーを診断ツールという用意された解決策へ戻せる。ページ全体を通じて「次に何をすればいいか」が常に提示される状態になる。

### 他ページへの影響

追加箇所は`build_index_page()`（TOP専用関数）内のみ。他ページの生成コードには一切触れない。診断ツール側（`build_diagnosis_tool()`）・診断ロジックも無変更（リンク先URLが増えるだけで、遷移先ページの実装・クエリパラメータ等は一切変更しない）。

### 回帰リスク

**極めて低い**。新規に増えるのは静的なテキストと`<a>`タグ1つのみで、JS・データ・アフィリエイトロジックへの影響はゼロ。既存の`.text-link`／`.price-meta`スタイルを流用するため新規CSSの副作用リスクもない。
