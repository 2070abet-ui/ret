### SERP構造（主要KW）

- 「宅配食 おすすめ ランキング 比較」: GYRO HOLDINGS（本業無関係の量産メディア）、マイベスト、DFS、伊坂酒造、竹野、EXIDEA + 宅配弁当比較.com・宅食ガイド等の小規模ニッチサイト。
- 「nosh 三ツ星ファーム 比較 どっち」: ほぼ全て個人ブログ・小規模メディアが上位。
- **判定**: 大手ポータル（価格.com的）の絶対支配はなく、個人でも同種のコンテンツで入り込める余地あり。ただし上位の量産型サイトは「記事数×比較テーブル」で大量に作っており、それだけでは差別化できない。

### AI検索リスク（定性評価）

- 「宅配食 どっちがいい」の一般比較はAI（ChatGPT/Gemini/Perplexity等）でも回答できる。
- しかし「**現在の初回キャンペーン・割引額・送料条件**」は頻繁に変わり、AIの回答は陳腐化しやすい。
- **「最新キャンペーンを最終確認日付きで提示する」**ことに価値がある。AIが「公式サイトで確認してください」としか答えられない部分が、本サイトの取り分になる。
- 独自の狙いどころ: 「nosh 初回クーポン」「nosh お試し 安い」等の**最新割引情報を求めるクエリ**。これはAIがリアルタイムに答えにくく、キャンペーンDBが直接答えられる領域。

## 5. 何を作るべきか（実装済み）

**「AIが生成できる文章」ではなく「継続的に蓄積する構造化データ＋自動更新システム」を構築した。**

```
ret/
├── data/                    # 独自DB（moatの中核）
│   ├── services.json        # サービスマスタ（7サービス登録済み）
│   ├── campaigns.json       # 初回キャンペーンDB（最短CV導線）
│   ├── menus.json           # メニュー別栄養DB（収集パイプラインで拡張）
│   ├── shipping.json        # 送料・解約条件
│   └── sources.json         # 出典URL・最終確認日台帳
├── config/
│   ├── affiliates.json      # アフィリエイトリンク管理（承認後にURL埋め込み）
│   └── watchlist.json       # 定期監視対象URL
├── tools/
│   ├── build.py             # 静的サイト生成（データ→HTML、依存ゼロ）
│   └── watch.py             # 価格・キャンペーン変更検知
└── site/                    # 生成された静的サイト
```

## 8. 自動化方針

- **build.py**: データをHTMLへ変換。全ページのヘッダー・フッター・内部リンク・sitemapを自動生成。
- **watch.py**: 公式サイトの価格・キャンペーン変更を検知（週1回想定）。スナップショットを`data/snapshots/`に保存。
- **affiliates.json**: アフィリエイトURLを一括管理。承認後1箇所書き換えるだけで全ページ反映。
- **今後の自動化候補**: メニュー栄養データの定期収集、キャンペーンDBの差分反映、記事の下書き自動生成。
- ※自動化が目的ではない。**「更新速度・情報精度・運用コスト」が改善する範囲でのみ自動化する**。
