## 0. 先に結論

**「AIが書いた文章っぽい」のは、語彙や業界用語（前回までに除去済み）ではなく、「構造の予測しやすさ」と「書き手の判断の不在」に原因がある。** 本文がデータベースの値をそのまま組み立てたテンプレ構成（全セクション同一型＋橋渡し文・読者案内の定型反復）になっており、読む前から次の文が読めてしまう＝AI生成文の定義そのものになっている。

Web調査（下記§1）でも、AIらしさの本質は「書き手にしか書けない情報（体験・固有名詞・自分で確かめた事実・個別の判断）が入っていないこと」という指摘が共通している。実体験は捏造できない（執筆原則8章）ため、解決策は「サイトが実際に行ったこと＝選択基準・確認して分かったこと・分からなかったこと」を本文に書くことで、捏造なしに書き手の存在を作る方向に絞る。

## 2. 対象記事の監査（本文計測＋エビデンス）

- 本文（`<main>`内の散文59文）を抽出・計測
- **読者案内・橋渡しの定型が集中**:
  - 「1社ずつ**見ていこう**」「三ツ星ファームを**見てみよう**」「回数の縛りがないサービスも**見てみよう**」「まとめて比較して**おこう**」
  - 「〜**してほしい**」（確認して／参考にして／読み比べて）×4、「〜も**どうぞ**」
- 5社カードが全社同一スキャフォールド（特徴箇条→気になる点箇条→送料行→CTA→橋渡し文）

## 3. 診断（AI特徴 ↔ 本文エビデンスの対応）

| 診断 | 該当AI特徴 | 本文の実例 |
|---|---|---|
| 読者を優しく案内する定型の反復 | ⑧⑥ | 「見ていこう／見てみよう／しておこう／してほしい／どうぞ」が節末・節冒頭に連発 |
| 型の均一（予測可能） | ①⑦ | 全カード同一構成、橋渡し文も「〜人には〜も候補になる／〜を見てみよう」のテンプレ |
| 書き手の判断・存在感がない | ③ | 本文はDB値の第三者中継のみ。主体は免責文だけ |
| 断定回避の緩い付け足し | ⑨ | 「置き場所に困る**こともありそうだ**」「〜**という進め方もある**」 |
| 語彙・人物カテゴリの単調 | ⑤⑥ | 「不安な人／心配な人／重視する人」の反復、文末が丁寧体＋助言形に偏る |

**結論**: 言葉ではなく「構造の予測しやすさ（①⑤⑥⑦⑧）」と「書き手の判断の不在（③）」。

## 4. 解決策（A〜F）

方針: **「DBの転記」→「人が調べて並べた記録」**。実体験を捏造せず（8章）、このサイトが実際に行ったことだけを本文に入れる。

| 対策 | 内容 |
|---|---|
| **A. 編集判断を入れる** | 「『一人暮らし向け』と公式で明記したのは◯社。ほかは明記がないが、単品購入という仕組みから候補に加えた」等の取捨選択を明示 |
| **B. 発見・未確認を正直に** | 「送料が『全国一律』と書けたのは◯社のみ。noshは13エリア、ワタミは郵便番号入力と『無料』と書けない理由が違った」「◯社は要確認」等 |
| **C. 橋渡し文の定型廃止** | 「〜見てみよう」をやめ、データ由来の問い（「では1食あたりの価格は？」）でつなぐ。文末パターンが1型に偏らない |
| **D. カードの型を崩す・表と本文の分担** | 全社同一形にせず、データの差（気になる点の数・送料の特異性）を本文の短文で語る。本文での送料の重複掲載はやめ表へ集約 |
| **E. 案内語の制限** | 「〜してほしい／〜どうぞ」類は記事1本2回まで |
| **F. レビュー観点の追加** | 執筆Skillの文章パスにAIらしさチェック（案内文密度・橋渡しの型・編集判断文の有無）を追加 |
