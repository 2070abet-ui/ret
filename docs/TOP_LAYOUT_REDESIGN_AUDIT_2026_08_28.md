# TOPページ レイアウト構造 再設計監査（2026-08-28）

**本監査は分析・提案のみ。コード・data/config・CSSの変更は一切行っていない。**

Playwright（Chromium）で `http://localhost:8791/`（TOP = `/index.html`）をPC（1440×900）・モバイル（375×812）で実際に開き、フルページ／ファーストビュー（スクロール前の1画面）のスクリーンショットと、DOM実測値（要素の位置・高さ・幅・個数）を取得して監査した。あわせて `tools/sitegen/templates.py` の `build_index_page()` とCSSトークン定義を突き合わせ、「見た目の印象」を「コード上のどの値が原因か」まで特定した。

## A. 現状TOPの最大のレイアウト問題 TOP5

### 1位：PC 1440pxで、画面幅の30%が死に空間のまま15枚のカードが単一カラムで縦積みされている

実測：`.container { max-width:1000px }` が全セクション共通で、1440px viewportでは左右に **220px ずつ（合計440px＝画面幅の30.5%）が完全な空白** になる。この余白の中で情報密度を上げる仕組み（2〜3カラム化等）が一切なく、15枚のサービスカードは幅1000pxの列の中に上から下へそのまま積まれる（`.service-list-section` の高さ実測 **3221px**＝ページ全体4713pxの68%）。結果、PCはモバイルを横に引き伸ばしただけの「縦に長いモバイルレイアウト」になっている（B・H2で詳述）。

### 2位：19個の白い角丸ボックスがほぼ同じ見た目で並び、セクションの境界が視覚的に読み取れない

Hero・検証カバレッジ・15枚のサービスカード・「このサイトのこだわり」カードの計19要素が、`.hero` `.trust-panel` `.card` `.svc-card` いずれも `background:#FFFFFF`・`border:1px solid` 系・`border-radius:10〜16px` という**ほぼ同一のスタイル**で描画される。ページ背景 `--color-bg:#FAF7F5` と カード背景 `--color-surface:#FFFFFF` の差はごくわずかで、色によるゾーニングが実質的に存在しない。「ここからここまでが1つの意味の塊」という認識を、罫線と影だけに頼っている状態。これが「情報自体は整理されているのにごちゃごちゃして見える」の最大要因。

### 3位：ファーストビューに「製品」が一度も登場しない

- PC（900px高）：Hero全体＋検証カバレッジ全体＋「目的で探す」の先頭がぎりぎり見える程度で1画面が終わる。サービスカードは1枚も見えない。
- モバイル（812px高）：Hero＋検証カバレッジの途中までで1画面が終わる。実際の最初のサービスカード（nosh）が現れるのは **スクロール1787px地点＝約2.2画面分下**（実測）。

「このサイトで何ができるか」はテキストでは説明されているが、「実際に選べる状態」を視覚的に一目で感じさせる要素（カード・写真・具体的な選択肢）が最初の1〜2画面に存在しない。

### 4位：15枚のサービスカードが情報構造・視覚的重みともに完全均一で、「作業的な反復」になっている

代表例（nosh）のカードDOM構成：タグ3個（低糖質/低塩分/冷凍）→「向いている人」1行→食べ方メモ1行→価格＋価格根拠バッジ＋検証バッジ（4要素）→CTA2個。これが**同一テンプレートのまま15回反復**される（実測：カード内要素数18、1カードあたり平均高さPC 201px／モバイル266px）。目的一致度・検証状況・価格帯による強弱が一切視覚化されないため、ユーザーは15枚を均等な集中力で読まざるを得ず、実際には多くが流し読み・離脱される典型的な単調リストになっている。

### 5位：内部CTAと外部（アフィリエイト）CTAが、確信形成前の段階で15回とも同格で並立している

`UI_DESIGN_PRINCIPLES.md` 5.2は「情報が不足している段階では外部CTAを主役にしない」「外部CTAは十分な情報を見せた直後に置く」と定め、同3.1はTOPを「発見」段階と位置づけている。しかし実際のTOPカードは、名前・価格・タグしか見せていない段階で「詳しく見る」（内部）と「公式サイトを確認」（外部・A8.net等）を**常に同じボタンサイズ・同じ行**で15回提示している。これは原則自体が禁じているタイミングでの外部CTA露出であり、視覚的にも「どちらを押すべきか」の判断コストを常時発生させている（詳細はH参照＝比較一覧・詳細ページのCTA遷移先自体は変更不可）。

## B. PC / モバイルそれぞれの問題

### PC（1440px）固有

| 問題 | 実測値 |
|---|---|
| 横幅を使わない | container 1000px、左右余白220px×2（画面の30.5%） |
| 縦スクロールが長い | ページ全体高さ **4713px** |
| サービス一覧だけで画面5.2枚分 | `.service-list-section` 高さ3221px（900px viewportの3.6倍） |
| 「目的で探す」のカラムが間延び | 5カラムのflexだが、各カラム内はテキストリンクのみで横幅に対して情報が薄い |

### モバイル（375px）固有

| 問題 | 実測値 |
|---|---|
| PCよりさらに長い | ページ全体高さ **6562px**（PCより1849px＝39%長い） |
| カードが縦に伸びる | 平均カード高さがPCの201pxから266pxへ32%増（テキスト折り返し増加） |
| 最初のカードまでが遠い | スクロール1787px（≒2.2画面）まで製品が1つも見えない |
| ファーストビューの情報量がPCより少ない | Hero＋検証カバレッジの途中までしか1画面に入らない（PCは目的で探すの先頭まで入る） |

### 共通の問題

- `.container { max-width:1000px }` はどのブレークポイントでも同一で、640px以下の `@media` は主に `padding` と `display:none/block` の出し分けのみ。**「読む配置」自体をPC/モバイルで作り分ける仕組みが存在しない**（構造レベルでは実質1レイアウト）。これは「装飾追加」ではなく構造の問題であり、今回の監査目的（8番）に直結する最大の技術的事実。

## C. 改善後の理想的なセクション構造

現状の要素（Hero／検証カバレッジ／目的で探す／キャンペーン／サービス一覧／このサイトのこだわり）は**すべて既存データ・既存コンポーネントで足りる**。並び順と視覚的な扱いを、ユーザーの意思決定順序に合わせて再編する。

```
① Hero＝価値提案＋確信の種（1画面で完結させる）
   「宅配食、どれを選べばいい？」＋一言リード＋検証数字の要約（例:32件確認済み）を軽量に統合
   ＋ primary CTA 1つ（診断）＋ secondary 1つ（比較一覧）　※現状の2CTA構成を維持

② スクリーニング＝目的で探す（主役に格上げ）
   Heroのすぐ下に。チップ→対象サービスの対応を今より大きく・見出し性を強める

③ 証拠ゾーン＝検証カバレッジ（独立した「帯」として差別化）
   背景色を変える／枠の太さを変えるなどでゾーン化し、①②と混同されないようにする
   （数値・凡例・文言は無変更、UI_DESIGN_PRINCIPLES.md 4.2.4「少ない数字も隠さない」を維持）

④ 今すぐ得する情報＝初回キャンペーン（現状維持）

⑤ 評価＝サービス一覧（情報階層とレイアウト密度を再設計）
   カード内の視覚優先順位：サービス名＝価格＝検証状態 を最上位、
   タグ・向いている人・食べ方メモは二次情報として弱める。
   PCは横幅を使うグリッド化（2〜3カラム）で「一覧性」を出す。

⑥ 締め＝このサイトのこだわり（フッター直前、現状維持で可）
```

ポイントは、①〜⑥のうち**新しく作る要素はゼロ**で、既存の6ブロックの「順序」「視覚的重み」「PCでの横幅の使い方」だけを変えるという点。

## F. 最も推奨する1案とその理由

**推奨：案1をベースに、案2の「検証カバレッジのゾーン化（背景色変更）」と「目的で探すの視覚的格上げ」だけを取り込んだ「案1＋α」。**

理由：

1. **制約適合度が最も高い**：新機能ゼロ・データ変更ゼロ・CTA遷移先不変という制約下で、A-1位（PCの横幅未活用）とA-2位（セクション境界不明瞭）という「最大の2つの問題」を、CSSの並び替えと背景色調整だけで直接解決できる。
2. **UI_DESIGN_PRINCIPLES.mdとの整合性が最も高い**：6.1節「タイポグラフィ・トークンによる情報の重み付けを一貫させる。装飾的な演出で重みを付けない」という原則に対し、案1＋αは既存の`--space-*`・`--color-surface-alt`トークンの使い分けのみで重み付けを作るため、原則に忠実。案3は「TOPに全社を出さない」という構造変更を伴い、8章「差別化要素のUI上の反映」との整合を別途検証する必要が生じ、監査の範囲を超える。
3. **回帰リスクが最小**：案2のHero統合・案3の社数間引きは、いずれもHero文言や一覧の情報構成そのものに手を入れるため、レビュー・QAの範囲が広がる。案1＋αはセクション単位の独立した変更なので、1つずつ検証・ロールバックしやすい。
4. **A-3位（ファーストビューに製品がない）は次点の改善対象として残す**：完全解決には案2相当のHero再構成が要るが、今回は「最小変更で最大効果」を優先し、まず境界の明確化とPCの横幅活用を先に着手する方が、投資対効果として合理的。

## G. 既存コードを最大限再利用した場合の実装範囲

対象ファイルは `tools/sitegen/templates.py` の1ファイルのみ（データ・生成ロジックには触れない）。

- `build_index_page()`（1634〜1732行目）：HTML出力の**並び順を入れ替えるだけ**（`{trust_html}` と `{purpose_html}` の順序、キャンペーンカードとサービス一覧の間隔調整）。新しいテンプレート関数は作らない。
- CSS（同ファイル冒頭のスタイルブロック）：
  - `.service-list-section` に `@media (min-width:900px)` の `display:grid; grid-template-columns` を追加（既存の`.svc-card`自体は無変更）
  - `.trust-panel` の `background` を `--color-surface-alt` 系に変更してゾーン化（既存トークンの再利用、新規カラー追加なし）
  - `.purpose-section` の見出しサイズ・余白を`--text-h2`相当に強め、Hero直下との連続性を作る
  - `.svc-card` 内の要素順（HTML生成順）を price → verification → target → meal_note の順に並び替え（`build_index_page()`内の文字列結合順を変更するのみ、CSSクラス自体は既存を使う）
- 影響範囲はTOPページ（`index.html`）のみ。`ranking.html`・詳細ページ・診断・比較ページは`.svc-card` `.trust-panel`等の同名クラスを共有しているため、**変更が他ページに波及しないよう、TOP専用の修飾クラス（例: `.svc-card-top-grid`）を追加する設計にする必要がある**（実装時の注意点として記録）。

## H. 変更してはいけない既存要素

- `data/services.json` / `data/campaigns.json` / `data/sources.json` 等のデータ構造・件数・記載順（サービスの表示順は「services.json記載順のまま変更しない」という既存ルール＝`vfull_badge()`のコメントに明記）
- `aff_link()` のロジック・アフィリエイトURL・rel属性
- 各CTAの遷移先（`href`）。内部CTA「詳しく見る」→詳細ページ、外部CTA「公式サイトを確認」→公式/アフィリエイトリンクという対応関係も不変
- SEO（title・meta description・canonical・sitemap生成ロジック）
- 検証バッジ（✓確認済み/≈算出値/⋯確認中/－未収集）のラベル・色・意味、および「サービスの優劣を示すものではない」という凡例文言
- `UI_DESIGN_PRINCIPLES.md` 8章の恒久方針：★評価・ランキング順位・偽の緊急性・sticky CTA・モバイルの強制カード化・出典/確認日の折りたたみを作らない
- 「1画面1主CTA」原則（5.3節）：再設計後もHero・各セクションの主CTAは1つに保つ
- 写真・画像を前提としない現状の構造（本監査自体もテキスト・バッジ中心の設計を維持する前提で提案している）
