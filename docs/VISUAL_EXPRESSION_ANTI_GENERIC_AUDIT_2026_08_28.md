## 0. 結論（先出し）

自サイトが「AIが作ったテンプレート」に見える最大の原因は、**構造そのものではなく、すべてのセクションが同じ視覚的処理（白/クリームの角丸ボックス＋細罫線＋薄い影）で描画されている均質さ**にある。実際、外部記事（Shuffle社ブログ等）が指摘する「AI生成サイトの型」＝「hero→3枚の特徴カード→信頼バッジ→CTA」は、自サイトのTOP構造（Hero→目的チップ→検証カバレッジ→サービスカード）とほぼ一致する。これは機能設計としては正しい（[[UI_DESIGN_PRINCIPLES.md]]が定義した意思決定順序そのもの）が、**すべてのセクションを同じ「角丸カード」という1つの部品で表現している**ことが「量産感」の正体である。

解決策は新しいコンポーネントを増やすことではなく、**同じ情報構造を保ったまま、セクションごとに「箱の見せ方」を意図的に変える**こと。具体的には、(1) 一部のセクションを箱から解放し全幅の色面にする、(2) タイポグラフィの強弱を数字・見出しで大胆につける、(3) 罫線・図形を最小限の装飾として使う、(4) バナー/キャンペーン枠を「箱の中の小さい要素」ではなく「独立した個性を持つゾーン」にする。いずれも新色・新機能・写真を必要としない。

## 2. 現サイトがAIっぽく見える原因（実機確認）

TOPページ（`index.html`）を実際にPlaywrightで確認した構造:

```
Hero（角丸ボックス、クリーム背景、影）
  ↓ 同じ余白
目的で探すチップ（角丸ボックス、薄オレンジ背景、影相当の色面）
  ↓ 同じ余白
検証カバレッジパネル（角丸ボックス、白背景、左罫線）
  ↓ 同じ余白
サービスカード×16（すべて同一の角丸ボックス、白背景、細罫線、影）
```

- **すべての箱が同じ`border-radius:var(--radius-md)`＋`box-shadow:var(--shadow-sm)`＋白/クリーム背景で描かれている。** 色相の違い（クリーム／薄オレンジ／白）はあるが、「形」「影の強さ」「余白の取り方」は完全に同一。これはコンポーネントライブラリ（Bootstrap的な「card」1種類を使い回す）の典型的な帰結で、外部記事が指摘する「AIはテンプレートの部品を並べる」という現象と一致する。
- **タイポグラフィの強弱が乏しい。** 見出し（h1/h2/h3）はサイズこそ段階的だが、フォントファミリー・字間・斜体などの「質感の違い」が一切なく、すべて同じゴシック体の太字。数字（価格・検証カバレッジ）も本文の1.4倍程度にしか大きくなっておらず、「ポスターのように大きい数字」という強いフックが無い（[[VISUAL_DESIGN_SYSTEM_AUDIT_2026_08_28.md]]で一部着手済みだが、まだ控えめ）。
- **グリッドが単調。** サービスカードは3列（PC）の均等グリッドで、大きさ・配置に一切の変化がない。Wirecutterの「サイドバー／特集／サイドバー」やスターバックスの「大1枚＋小2枚」のような非対称配置が無い。
- **図形・罫線が「区切り」以外の役割を持たない。** 罫線は`border:1px solid`のみで、装飾としての罫線（見出し下の太い罫線、斜めの区切り等）が一切無い。
- **余白のリズムが一定。** セクション間の余白は`--space-4`〜`--space-5`でほぼ一定に保たれており、「ここで一度大きく間を取る」という緩急が無い。

**結論**: 機能面の構造（1ページ1意思決定ステップ）自体は正しく、変更すべきではない。「AIっぽさ」は構造の問題ではなく、**全セクションが同一の「箱」表現に閉じ込められていること**が原因。

## 3. 人間がデザインしたように見えるサイトの共通点

実機調査（§1）から抽出した共通パターンは以下の4点に整理できる。

### 3.1 「箱」に頼らない箇所がある
ほぼ日は本文セクションを一切カード化せず、白地に直接テキストを流し込む（≒新聞・雑誌の紙面感）。Wirecutterも記事一覧はカードではなく罫線区切りの縦リスト。**全部をカードにしない**こと自体が「人間らしさ」の最大の要因。

### 3.2 タイポグラフィが「地の文」と「主張」を明確に分けている
GRAZAは見出しに大ぶりのセリフ体（本文とは全く違う書体）を使い、しかも2行の見出しを意図的に左右にずらして配置する。Wirecutterは極太のスラブ書体見出し＋太い黒罫線という「新聞の一面」的な強いコントラスト。**サイズだけでなく書体・配置のズレで「主張」を作っている。**

### 3.3 図形・イラストは「装飾」ではなく「記号」として最小限使われる
GRAZAの線画イラスト（オリーブから雫が垂れる絵＋「DRIP」という擬音語テキスト）は1色・1本の線のみで、情報量は少ないが「誰かが手で描いた」という痕跡がある。Wirecutterの特集画像も、写真の切り抜きと幾何学図形（丸・三角・等高線パターン）を組み合わせたコラージュで、単なる商品写真ではなく「編集された」感じを与える。

### 3.4 非対称なグリッドで「情報の重み」を可視化している
スターバックスのバナーは「大きい1枚＋小さい2枚」という非均等な配置で、どれが一番重要かが一目でわかる。Wirecutterの3カラムも幅が均等ではなく、中央の特集が最も広い。**同じ大きさのボックスを並べない**ことで、優先順位そのものが視覚化されている。

| 幾何学図形のコラージュ（丸・三角等の単色シェイプ） | Wirecutter | 検証カバレッジや価格帯を表す円グラフ的な単色の円・バーなど、既存の`trust-bar`（進捗バー）の発想を拡張し、単色の図形を背景装飾として控えめに使う |

## 5. バナー / キャンペーンブロックの活用案

現状の「初回キャンペーン・お試し情報」ブロック（TOP）は、他のカードと同じ白背景の箱の中に箇条書きリンクが並ぶだけで、「広告枠」にも「特集」にも見えない中途半端な扱いになっている。

### 5.1 「サイトの世界観に合う特集ブロック」として成立させる条件
- **広告であることを隠さない**: 既存の「PR」表記方針（フッターの開示文）を保ったまま、キャンペーンブロックの見出しに「PICK UP」「初回キャンペーン特集」等、通常のセクション見出しより一段強いトーンを与える。
- **均等グリッドにしない**: スターバックス型の「大1枚（一番お得・確認済みのキャンペーン）＋小2〜3枚（その他）」という非対称配置にする。既存データ（`campaigns`の`requires_verification`で確認済みを優先する既存ロジックがすでにある）をそのまま使い、表示サイズだけを差別化する。
- **色面で区切る**: 現状の白背景カードではなく、ページ背景色とは異なる帯（既存の`--color-primary-subtle`または`--color-surface-alt`）で「ここは特集ゾーンだ」と一目で分かるようにする。新色は不要。
- **CTAは煽らない**: 「今すぐ」「残りわずか」等の緊急性演出は禁止事項どおり導入しない。「確認済みの実額」という既存の誠実な訴求をそのまま使う。

### 5.2 具体案（新機能・新データ不要）
1. TOPの「初回キャンペーン・お試し情報」を、既存の3件表示はそのまま、**1件目だけ大きな枠**（実額を大きな数字で表示）＋残り2件を小さい枠、という非対称レイアウトにする。
2. 比較一覧の「選び方のポイント」ブロックも、単なる箇条書きではなく、既存文言のまま「1点だけ強調表示、残りは通常表示」という強弱をつける。

## 6. やらない方がいい表現

ユーザー指定の禁止事項をそのまま踏襲し、それぞれ**このサイトの文脈でなぜダメか**を明記する。

| 禁止表現 | このサイトで避けるべき理由 |
|---|---|
| 紫/青系グラデーション | ブランドカラー（暖色オレンジ＋クリーム）と衝突し、かつ「AI/SaaSスタートアップ感」の最も典型的な記号。誠実な情報サイトという position と矛盾する |
| ガラスモーフィズム（すりガラス効果） | 装飾が情報より目立ち、「検証状態を数値の根拠として一体化させる」という[[UI_DESIGN_PRINCIPLES.md]]4.2の原則に反する |
| 過剰な角丸 | 現状の`--radius-sm/md/lg`（6/10/16px）はすでに控えめで適切。これ以上丸めると「AIが作った丸っこいSaaS UI」に近づく。**現状維持でよい** |
| 過剰なドロップシャドウ | 現状の`--shadow-sm/md`もすでに薄い。追加の強い影は不要、むしろ§4のように**影を無くす箇所を増やす**方向が正しい |
| 絵文字 | 検証状態バッジ（✓≈…—）という記号ボキャブラリーが既に確立しており、絵文字を混ぜると誠実さのトーンが崩れる |
| 不必要なアイコン | §4で提案した「保存方法アイコン」等は**最小限・単色・1箇所の意味づけのみ**に限定する。ナビゲーションや見出し全部にアイコンを付けるような氾濫はしない |
| ★評価・王冠・ランキング | [[UI_DESIGN_PRINCIPLES.md]]8.1の恒久方針と一致。今回のグラフィック強化でも数値化・序列化には一切使わない |
| 写真の無理な追加 | [[PRODUCT_IMAGE_LICENSING_AUDIT_2026_08_27.md]]の結論を維持。本監査の提案（§4）はすべて写真代替の表現のみ |
| 新機能の追加 | 本監査は既存データ・既存コンポーネントの「見せ方」の変更のみを対象とする |

**境界線（「やりすぎ」との違い）**: 外部記事の指摘どおり「グリッドを崩すことが意図的に見えるのは、土台の構造がしっかりしている場合だけ」。本監査の提案はすべて**既存のページ構造・情報順序・CTA配置を変えず、視覚的な処理だけを変える**ため、この境界を超えない。逆に、複数の非対称パターンを1ページに詰め込みすぎる（例: 全セクションを毎回違う形にする）と一貫性が失われ「バラバラ」に見えるため、**非対称・脱カード化は「本当に目立たせたい1〜2箇所」に限定する**のが安全策。

## 8. 優先順位

| 優先度 | 項目 | 理由 |
|---|---|---|
| P1 | セクションの「脱カード化」（1〜2箇所を色面ベタ塗りに） | 最も費用対効果が高く、既存トークンのみで実現可能。「AIっぽさ」の最大要因に直接効く |
| P1 | 見出し・数字のタイポグラフィ強弱の拡大 | [[VISUAL_DESIGN_SYSTEM_IMPLEMENTATION_PLAN_2026_08_28.md]]項目4で着手済みの延長線上。数字サイズと余白を強める |
| P2 | キャンペーンブロックの非対称レイアウト化 | 「広告に見えて広告っぽくない」バランスの実現に効果大だが、レイアウト実装の手間はP1より大きい |
| P2 | セクション見出し下の太罫線・区切り強調 | 低リスク・低コストだが、単体では効果が限定的なため中優先度 |
| P3 | 最小限の線アイコン（保存方法等）の導入 | 効果はあるが「不必要なアイコン」との境界が繊細なため、慎重な検討を要する |
| P3 | 見出しの段違い配置・軽微な回転装飾 | 効果はあるが細部の調整であり、他の変更が定着してから着手すべき |

- `data/*.json`・`config/*.json`は本監査で参照のみ、変更なし。
