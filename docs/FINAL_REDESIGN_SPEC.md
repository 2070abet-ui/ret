# 宅食図鑑 全面リデザイン 最終設計書（2026-08-27）

作成日: 2026-08-27
作成者: Claude Code
基準文書: `docs/REDESIGN_COMPETITIVE_AUDIT.md`
範囲: 本ドキュメントは**設計のみ**。コード/data/config変更・build・commit・push は一切行っていない。
目的: 競合成功サイトの購買導線をBASELINEとして取り込み、当サイト固有の「値単位の出典・確認日・検証状況」という差別化資産を最大限可視化する最終設計を確定する。

---

## 1. リデザイン方針

**「比較 → 納得 → 信頼 → 公式サイトクリック」を最短化する。見た目の刷新は目的ではない。**

3つの原則を置く。

1. **競合が既に確立した購買導線パターン（結論の先出し・向いている人の早期提示・条件別導線・明確なCTA階層）は、独自性を主張せず素直に取り込む（BASELINE化）。**
2. **独自資産（値単位の出典・確認日・検証状況ダッシュボード）は、現状サービス詳細ページの奥に沈んでいる。これをトップページ・ranking.htmlという意思決定の早い段階まで引き上げる。**
3. **新しい機能を作ることを目的にしない。** 根拠のないランキング・★評価・ブラックボックススコア・偽の緊急性は作らない。3つの差別化候補（4章）以外に新規機能は追加しない。

## 2. 競合BASELINE（取り込みを決定した購買導線パターン）

`REDESIGN_COMPETITIVE_AUDIT.md`の実地調査に基づき、以下を**BASELINEとして全面的に取り込む**（独自性は主張しない、競合水準への追随として実施）。

| パターン | 根拠 | 取り込み先 |
|---|---|---|
| 結論を先に提示する | silver-choice.jp「迷ったらコレ」を本文前に先出し | TOP・ranking |
| 「向いている人」を価格より前に提示する | silver-choice・my-bestとも価格提示より前に配置 | service detail |
| 条件別の選択導線 | silver-choice「むせやすい→A社」等の条件直結、個人サイトの目的別TOP3カード | TOP・ranking |
| 価格・送料・キャンペーンの具体的な数値表示 | cachie・my-bestとも金額を明示。当サイトはcampaigns.htmlでは既に実現済みだがTOPページは未達（3章） | TOP（是正） |

### 候補1: トップページへの検証カバレッジ表示

| 評価項目 | 内容 |
|---|---|
| 意思決定の改善 | 「このサイト全体はどこまで裏付けがあるか」を3秒で把握できる。個別ページに行かないと分からなかった情報を最初に提示する |

## 5. ranking.htmlの再設計（名称問題の最終判断）

### 5.1 「ランキング」を維持する根拠の検証

現状のranking.htmlは`services.json`の記載順（データ追加順）で11社を並べているだけであり、**価格・人気・満足度いずれの基準による順位付けも行っていない**。「ランキング」という名称は、ユーザーに「1位が最もおすすめ」という期待を抱かせるが、その期待に応える実装が存在しない。

検討した3つの選択肢:

| 案 | 内容 | 判定 |
|---|---|---|
| A. 現状維持（名称のみ「ランキング」を続投） | 何もしない | **却下**。名称と実態の不一致がそのまま残り、`SITE_UX_INTEREST_AUDIT_2026_08_26.md`以来の指摘が放置され続ける |
| B. 「全項目確認済み」を機械的な順位基準として採用し、確認度順に並べ替えて「ランキング」を名乗り続ける | 候補2のバッジ該当社を上位に固定表示 | **却下**。「確認できている項目数」は当サイト内部の作業進捗であり、「どのサービスがユーザーにとって優れているか」という価値判断ではない。これを根拠に1位・2位と序列化することは、ユーザーには「このサービスが一番良い」と誤読される可能性が高く、**本サイトが禁じてきた「根拠のないランキング」に該当するリスクがある** |
| C. ページの呼称を「ランキング」から**「比較一覧」**へ変更し、順位付けそのものをやめる | H1・タイトル・meta descriptionの文言変更のみ。URLは`ranking.html`のまま維持（SEOへの影響を避けるため） | **採用** |

### 5.2 決定

**ranking.htmlは「ランキング」という呼称をやめ、「宅配食 比較一覧」に改める。** 順位（1位・2位…）は一切付けない。行の並び順は現状の`services.json`記載順を維持する（これも恣意的な追加順であり、変更によって新たな序列を作らない）。

「全項目確認済み」バッジ（候補2）は各行の**事実表示**として設置するが、そのバッジの有無で行の並び順を変えない。バッジの凡例に「これは総合評価ではなく、価格・送料・初回キャンペーンの3項目を公式一次情報で確認できているかどうかの表示です」と明記し、序列化の意図が無いことを明確にする。

URL（`ranking.html`）・ナビゲーションのリンク先は変更しない。変更するのはページ内のH1・タイトルタグ・meta description・本文中の「ランキング」という文言のみ（実装時にnav文言「おすすめ比較」も「比較一覧」に統一するかは実装時に判断、本設計では必須としない）。

## 11. campaigns設計

現状の設計を**維持する**。3章の確認の通り、確認済みのキャンペーンには既に実額（例:「初回¥1,500 OFF＋継続割引」）が表示されており、未確認のものは「要確認」と正直に表示されている。競合水準を満たしているため、追加の設計変更は無い。

## 13. 共通UI/CTA設計・モバイル設計・分類まとめ

### 13.1 CTA設計
- 既存の2階層（詳しく見る／公式サイトを確認）を維持する。**作り直さない**。
- サービス詳細ページのみCTA回数を2→3に増やす（8章）。他ページのCTA回数は変更しない。
- CTA文言への実額反映（例:「初回26%OFFで公式サイトを見る」）は**DATA FIRST/計測待ちのためDEFER**（Phase4で導入したGA4のベースライン計測後に判断）。ただしTOPページのキャンペーン欄への実額反映（6章）は文言最適化ではなく**情報の正確性の是正**であり、これとは区別して先行実施する。

### 13.2 モバイル設計
- 横スクロール＋案内文言方式を維持（変更しない）。カード化はしない。
- sticky CTAは実装しない（競合6サイトに実装なし、根拠不十分、`REDESIGN_COMPETITIVE_AUDIT.md`12章のDEFERを追認）。
- 出典・確認日は折りたたまない（差別化情報を隠さない）。
- 新規追加要素（目的別導線カード・こんな方におすすめ・FAQ・結論の先出し・差分強調・集計サマリー）は、いずれも既存`.card`コンポーネントの範囲内で実装可能であり、モバイル専用の新規CSSは不要。

### 13.3 最終分類

| 分類 | 項目 |
|---|---|
| **MUST MATCH** | TOPページのキャンペーン表示に実額を反映／service detailの「こんな方におすすめ」早期セクション／TOPの目的別導線カード |
| **COPY BASELINE** | service detailのCTA回数を2→3に／確認日のH1直下再掲／diagnosis結果の上位3件キャップ＋一致理由／FAQセクション新設（確信度中） |
| **DIFFERENTIATE** | 検証カバレッジ表示（TOP・ranking・verification共通ロジック）／「全項目確認済み」バッジ（ranking、序列化はしない）／比較ページの差分自動強調（結論の先出し・向いている人の差分） |
| **DATA FIRST** | ranking（比較一覧）の価格ソート・フィルタ／CTA文言の実額反映／診断ツールの価格フィルタ |
| **DO NOT BUILD** | ranking.htmlの数値順位付け（★評価・スコア・確認度による序列化を含む、5章）／sticky CTA／モバイルのカード化／出典・確認日の折りたたみ／偽の緊急性演出／推薦エンジン・matching DSL |
