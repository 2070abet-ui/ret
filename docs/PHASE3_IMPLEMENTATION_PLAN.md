### 2.4 設計判断

- **表示列の追加が前提**: フィルタ機能だけでなく、テーブルに「保存方法」列自体を追加する（現状は列が無いため、フィルタで絞り込んでも残った行がなぜ残ったのか視認できない）。列追加はテンプレートの`<tr>`生成部分（`templates.py:379-389`）に1セル追加するのみ。
- **UI方式**: 診断ツールのような結果再描画ではなく、`<tr>`に`data-mealform="冷凍 冷蔵"`等の属性を付与し、チェックボックス変更時にJSで`display:none`を切り替える方式にする（診断ツールとロジックは共有（`meal_form_categories`の正規化結果を埋め込むだけ）だが、UI実装は別・より軽量にする＝重複を最小化）。
- **価格フィルタとは明確に分離**: ranking.htmlの価格軸ソート/絞り込みは`PHASE3_COMPETITIVE_REAUDIT.md`の通りDATA FIRST（price confirmed 6社以上）のまま据え置く。保存方法フィルタの追加が価格フィルタの前倒しを意味しない。
- **matching engine化しない**: 目的タグとのスコアリングは追加しない。あくまで「保存方法という1軸のAND絞り込み」のみ。診断ツールへの誘導文言（「目的から選びたい方は診断ツールへ」）を添えて、役割分担を明示する。

### 2.5 候補2の結論

### 3.1 現行repoの実測（安全性の観点で最重要）

`data/sources.json`を全件確認した結果、**現状のsources.jsonをそのまま一覧公開することは安全ではない**ことを確認した。

| 種別 | 該当エントリ例 | 問題 |

### 3.2 設計方針の確定：「sources.json全件表示」ではなく「検証状況ダッシュボード」

以上の理由から、当初案（sources.jsonの内容整理・公開）をそのまま実装するのはリスクがある。安全かつユーザー指示（「単なる出典一覧ページで終わらず、検証可能性を実際のユーザー価値に変換できるか評価する」）に応える設計として、以下に変更する。

**このページは`sources.json`を直接ループしない。** 代わりに、既にPhase1/Phase2で実装済みの検証状態ロジック（`_price_status` / `_shipping_status` / `_campaign_status` / `vstatus_badge` / `source_link`、いずれも`templates.py`内の既存関数）を**11社×3フィールド（33マス）に対してそのまま再利用**し、1ページに集約表示する「検証状況ダッシュボード」として実装する。

- 各マスは既存のバッジ（確認済み/算出値/確認中/未収集）をそのまま表示する。
- `source_id`が存在するマス（現状10マス、7つの出典に対応）にのみ、既存の`source_link()`がそのまま出典リンクを追加する。
- **noteフィールドは一切表示しない**。表示するのは`sources_by_id`の`url`と`confirmed_at`のみ（`source_link()`の既存実装と同一）。
- `sources.json`をループする新しいコードは書かない。33マスのループは`services`/`shipping_by_id`を既存の`_price_status`等でループするだけで、これは`build_ranking_page`や`build_service_page`と同じパターンの流用。

この設計により、**新しい情報は一切公開されず**（Phase2で既に個別ページに出ているものの集約に過ぎない）、かつ「11社を通じてどこまで検証できているか」を一望できる、既存の個別表示には無い価値を提供する。

### 3.3 評価

| 項目 | 内容 |
|---|---|
| 分類 | **DIFFERENTIATE**（`PHASE3_COMPETITIVE_REAUDIT.md`で確認済みの通り、値単位の出典・確認日紐付けは5競合いずれにも存在しない。今回の設計変更後もこの差別化の性質は維持される。「検証状況を1ページに集約する」という形自体も、cachie（サービス紹介文中に散発的出典）等の実装には無い） |
| ROI | 中。実装コストは低い（既存関数の再利用、新規データ・新規ロジックなし）が、ページとしての体裁（表デザイン等）に多少の工数がかかる |
| 期待効果（根拠付き） | **CV効果は主張しない**（このページ自体は取引を促す構成ではなく、直接のCV導線ではない）。**SEOの直接的な順位効果も主張しない**。効果があるとすれば、「一次情報を個別に確認しながら運用している」という主張を裏付ける独立した証拠ページとして、Googleの品質評価やASP審査時の心証、あるいは既存訪問者の信頼感に働く可能性がある**間接的・不確実な効果**にとどまる。定量化はGA4導入後も直接測定できない性質の効果である点を明記する |
