## 3. 実装とサイトの主張の不整合（今回新たに実測で確認した事実）

いずれも自分でgrep等により直接検証済み。

### 3.1 sitemap.xmlの`lastmod`固定
```
$ grep -o "<lastmod>[^<]*</lastmod>" site/sitemap.xml | sort -u
<lastmod>2026-08-26</lastmod>
```
23ページ全てが同一の`2026-08-26`。Phase1（`b13d585`、08-27相当のデータ更新）・Phase2（`2d211d5`）のデータ変更後も更新されていない。**検索エンジンに「このページは変わった」という鮮度シグナルを一切送れていない**。サイトのコンセプトが「継続的に正確に保つ」ことである以上、この欠落は競合以前の自己矛盾。

### 3.2 フッター「最終更新」表示のハードコード
```
$ grep -rc "2026-08-26" site/*.html site/services/*.html
（17ファイルでヒット、うち services/chef-muten-tukuritoki.html だけで5箇所）
```
`page_footer("2026-08-26")`という固定文字列が全ページで使われており、`data/*.json`の実際の`updated_at`（08-27）から動的生成されていない。値単位の出典日（`sources.json`由来）は正確だが、**ページ単位の更新日表示は不正確なまま1日遅れて固定**されている。

### 3.3 比較ページの孤立
```
$ grep -rl "comparisons/" site/index.html site/ranking.html site/campaigns.html site/services/*.html site/tool/*.html
（該当なし＝0件）
```
`comparisons/*.html`3本へのリンクは、sitemap.xmlと比較ページ自身の相互リンク以外に**サイト内のどこにも存在しない**。SITE_UX_INTEREST_AUDIT（P0-4/P1-2）が指摘した「診断結果→サービス詳細」「サービス詳細→関連サービス」は既に是正済みだが、比較ページへの導線だけが是正対象から漏れている。

### 3.4 JSON-LDが`WebSite`型のみ
```
$ grep -oh '"@type"[^,]*' site/*.html site/services/*.html site/comparisons/*.html site/articles/*.html site/tool/*.html
"@type": "WebSite"
```
サイト全体で唯一の構造化データが`WebSite`。今回実地確認したmy-best.com（16社ランキング/高齢者16社ランキング）は`BreadcrumbList`等の構造化データの痕跡を確認済み。パンくずリスト自体（視覚要素）もサイト内に存在しない。

### 3.5 ranking.htmlに保存方法フィルタが無い
Phase2で診断ツールに実装したmeal_form軸（冷凍/冷蔵/日配、11/11社確認済み）は、ranking.htmlには転用されていない（Phase2計画で意図的に対象外としたのは価格軸ソートのみのはずだが、結果的に保存方法フィルタも一緒に見送られている）。my-bestは実地確認で「保存方法」フィルタをranking形式の比較表に実装済み。

### 3.6 軽微な事項
- ranking.html/index.htmlのmeta descriptionがほぼ同一文言で差別化が弱い。
- 非提携6社の公式直リンクに`rel="nofollow sponsored"`が付与されており、`sponsored`属性の意味（広告・アフィリエイト由来リンク）と実態（非提携の通常リンク）がズレている。実害は小さいが技術的には不正確。
- README.mdが記載する公開URL（`https://takushokuzukan.workers.dev`）と、`config/site.json`/`wrangler.toml`が指す実際のデプロイ先（`https://ret4853.2070abe.workers.dev`）が異なる。`wrangler.toml`のコメントから、`takushokuzukan`という名前が確保できずWorker名が`ret4853`になった経緯が読み取れる。**サイト本体のcanonical/OGP/sitemapは実際のデプロイ先と自己整合しており技術的な破損ではない**が、README（ASP申請時などに参照される可能性がある文書）が古いままである点はドキュメントの整合性問題として残る。

| 6 | 疑似口コミ・レビューセクションの追加 | cachie/my-bestは実装済みだがbenikomachi/silver-choiceには無く、業界標準ではなく一部競合のみの機能。かつ自社は実データを持たず、以前「内部管理情報の露出」を是正した経緯（P0改善）と同種の信頼性リスクを再導入することになる |
| 7 | 全社全フィールドへの出典紐付け拡張 | A8承認5社の3フィールドに限定（Rule of Three）を維持 |

## 6. 結論

### 現時点で最もROIが高い次の1〜3施策

1. **サイト基礎衛生の一括是正**（5.1節#1〜4）: sitemap.xmlのlastmod動的化、フッター更新日の動的化、比較ページへの内部リンク追加、JSON-LD拡充。いずれも新規データ・新機能ゼロで、SEOクロール性・鮮度シグナル・回遊・信頼性訴求を同時に改善する。実装コストが最も低く、根拠（自社の主張との矛盾を直接解消する）が最も明確なため最優先。
2. **ranking.htmlへの保存方法フィルタ追加**（5.1節#6）: データは11/11社で確認済み、診断ツールの既存ロジックを転用するだけで実装できる。my-bestの実地確認済み競合標準に対する唯一の未達項目。
3. **一次情報ソース台帳ページの新設**（5.2節#2）: 既存の値単位出典という差別化を、ゼロ新規データで一段引き上げる。11社規模だからこそ実現可能で、競合5サイトいずれにも存在しない。

### 実装しない方がいい施策

- 減塩/無添角/高タンパク/高齢者のTheme本体構築（今回の再調査でむしろ競合スケールの劣位が悪化・確認された）
- 診断ツールの多段階ウィザード化（比較サイト業態に競合実装が存在しない）
- 疑似口コミ・レビューセクションの追加（実データが無く、既に是正済みの信頼性リスクを再導入する）
- 計測基盤の無いままのCTA文言全面刷新（施策自体は妥当だが、GA4導入前に本体着手するとROI未検証のまま資産を投じることになる）
- 推薦エンジン・汎用テーマ基盤・データ変更履歴機能（恒久NO-GO、変更なし）

### 今後の差別化の核心

値単位の出典・確認日リンクという既存差別化は、5競合サイトの再検証でも揺るがず健在である。しかし今回の監査が示すのは、**新しい差別化機能を追加するより先に、既に持っている差別化の「主張」と「実装」を完全に一致させることの方が優先度が高い**という事実である。鮮度を差別化の中核に据えながらsitemapとフッターの更新日が実データより古いまま固定されている状態は、ユーザーに気づかれた瞬間に信頼を損なう自己矛盾である。Phase3の核心は、11社という規模を活かして「検証できる範囲だけを、値の単位で検証した状態のまま見せ続ける」という運用密度を、サイトの隅々（sitemap・フッター・内部リンク・構造化データ）まで一貫させることにある。その上で唯一の新規差別化候補（一次情報ソース台帳ページ）を足すことが、過剰な機能拡張をせずに済む、最も筋の良い次の一手である。
